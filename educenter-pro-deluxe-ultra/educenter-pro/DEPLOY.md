# Запуск EduCenter PRO для реальных учеников

Этот файл — про боевой запуск. Для знакомства и разработки хватит Live Server (см. README.md).

## 1. Что получится

Один Node-процесс отдаёт сайт и API, данные лежат в одном файле `db.json`. Зависимостей нет (`npm install` не нужен), нужен только **Node 18+** (рекомендуется 22).

В боевом режиме база создаётся **чистой**: нет ни демо-учеников, ни демо-паролей. Единственный пользователь — администратор, которого вы задаёте переменными окружения. Дальше всё делается из кабинета администратора: преподаватели, группы, ученики, расписание, награды.

## 2. Первый запуск

Linux / macOS:

```bash
EDUCENTER_MODE=production HOST=0.0.0.0 PORT=3000 \
ADMIN_LOGIN=owner ADMIN_PASSWORD='Ваш#Пароль2026' CENTER_NAME='Название школы' \
DATA_DIR=/var/lib/educenter node server.js
```

Windows (PowerShell):

```powershell
$env:EDUCENTER_MODE="production"; $env:ADMIN_PASSWORD="Ваш#Пароль2026"; $env:ADMIN_LOGIN="owner"; node server.js
```

- Пароль администратора: минимум 8 символов, буквы и цифры. Без него сервер при первом старте **не запустится**.
- `ADMIN_PASSWORD` нужен только при самом первом запуске, пока нет `db.json`. Потом переменную удалите: в базе хранится только хеш.
- Сразу после входа смените пароль в «Профиль и настройки».
- Все переменные: `PORT`, `HOST`, `DATA_DIR` (где лежит база), `CENTER_NAME`, `HSTS=1` (только за HTTPS), `EDUCENTER_MODE=production`.

## 3. HTTPS обязателен

Пароли идут по сети, поэтому открывать сайт ученикам можно только по HTTPS. Самый простой путь — Caddy перед приложением (сертификат он получает сам):

```
school.example.com {
    reverse_proxy 127.0.0.1:3000
}
```

После этого запустите приложение с `HSTS=1` и `HOST=127.0.0.1` (наружу смотрит только Caddy).

## 4. Автозапуск (systemd)

`/etc/systemd/system/educenter.service`:

```ini
[Unit]
Description=EduCenter PRO
After=network.target

[Service]
WorkingDirectory=/opt/educenter-pro
Environment=EDUCENTER_MODE=production HOST=127.0.0.1 PORT=3000 DATA_DIR=/var/lib/educenter HSTS=1
User=educenter
Restart=on-failure
ExecStart=/usr/bin/node server.js

[Install]
WantedBy=multi-user.target
```

Первый запуск с `ADMIN_PASSWORD` сделайте вручную (п. 2), затем включайте службу.

## 5. Docker (вариант)

```bash
docker build -t educenter .
docker run -d --name educenter -p 127.0.0.1:3000:3000 -v educenter-data:/data \
  -e ADMIN_PASSWORD='Ваш#Пароль2026' -e ADMIN_LOGIN=owner educenter
```

Данные живут в томе `educenter-data`. Проверка здоровья встроена (`/healthz`). Dockerfile в этой сборке не запускался на тестовой машине (там нет Docker) — проверьте сборку у себя.

## 6. Резервные копии — делайте с первого дня

```bash
DATA_DIR=/var/lib/educenter BACKUP_DIR=/var/backups/educenter KEEP=30 node scripts/backup.mjs
```

Копия безопасна во время работы сервера (файл заменяется атомарно). Ежедневно через cron:

```
15 3 * * * cd /opt/educenter-pro && DATA_DIR=/var/lib/educenter BACKUP_DIR=/var/backups/educenter node scripts/backup.mjs
```

Копии лежат на том же сервере — раз в неделю забирайте их ещё и **в другое место**. В них есть персональные данные учеников и хеши паролей: права `600`, доступ только вам.

Восстановление: остановить сервер → скопировать нужный `db-….json` в `DATA_DIR/db.json` → запустить.

## 7. Обновление

Остановить службу → сделать резервную копию → заменить файлы (папку `data` и `DATA_DIR` не трогать) → запустить. Формат базы пока не менялся; если он изменится, это будет указано отдельно.

## 8. Проверка после запуска

- `https://ваш-домен/healthz` отвечает `{"ok":true}`;
- на странице входа нет блока «Демо-доступ»;
- вход демо-логинами (`dilshod`, `nargiza`) не работает;
- `https://ваш-домен/data/db.json` и `/server.js` отвечают 404.

## 9. Честные ограничения

- **Файл вместо базы данных.** Подходит для одной школы (десятки групп, сотни учеников). Весь файл читается и записывается целиком при каждом изменении, поэтому при тысячах активных пользователей понадобится настоящая СУБД.
- **Один процесс.** Не запускайте две копии на одну базу — они затрут изменения друг друга.
- **Сессии** живут 8 часов и хранятся в самой базе. После 5 неверных паролей вход для этого логина блокируется на минуту (защита от подбора, но чужой может так мешать входу — при необходимости ограничивайте частоту запросов на уровне Caddy/nginx).
- **Нет отправки писем и SMS.** Забытый пароль ученику сбрасывает администратор («Аккаунты учеников → Сбросить пароль»).
- **Нет редактирования и удаления** групп, преподавателей и занятий через интерфейс (только создание); ученика можно отключить, но не удалить. Для срочной правки данных остановите сервер и правьте `db.json` аккуратно, предварительно сделав копию.
- **Фото и файлы работ** хранятся прямо в базе (ограничения размера есть), поэтому файл растёт быстрее, чем кажется.
