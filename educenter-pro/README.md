# EduCenter PRO — кабинет ученика

Личный кабинет ученика учебного центра: главная, расписание, посещаемость, успеваемость, домашние задания, EduCoins, достижения, уведомления, профиль, настройки. Светлый интерфейс, адаптивный (ПК, планшет, телефон), без внешних зависимостей и сборки.

## Запуск

**Вариант 1 — VS Code Live Server (проще всего)**
1. Откройте папку `educenter-pro` в VS Code.
2. Установите расширение *Live Server*.
3. ПКМ по `index.html` → **Open with Live Server**.
4. Войдите: логин `dilshod`, пароль `Student#2026` (кнопка «Подставить данные» на странице входа).

В этом режиме «сервер» работает прямо в браузере и хранит данные в localStorage. Файл через двойной клик (`file://`) работать не будет — нужен именно Live Server.

**Вариант 2 — настоящий сервер (рекомендуется для проверки прав доступа)**
```
npm start            # или: node server.js   (нужен Node.js 18+)
```
Откройте http://localhost:3000. Данные хранятся в `data/db.json`, все проверки прав выполняются на сервере. Чтобы открыть сайт с телефона в той же Wi-Fi сети: `HOST=0.0.0.0 npm start`.

**Сброс демо-данных:** режим Live Server — очистить данные сайта в браузере (ключ `educenter.db.v1`); режим Node — удалить `data/db.json`.

## Как устроено

```
index.html, student.html     страницы входа и кабинета
css/                         дизайн-система: foundation (токены) → layout → components → pages
js/app.js                    оболочка, навигация, роутер (#/overview …), состояния загрузки/ошибок
js/ui.js, js/components.js   безопасные шаблоны (автоэкранирование), иконки, диалоги, график, общие компоненты

js/server/                   бэкенд: core (правила), views (чтение), backend (авторизация и права), seed, util
server.js                    необязательный Node-сервер (без зависимостей)
tests/                       авто-тесты бэкенда (node --test) и сценарии браузера (Playwright)
```

### Правила данных
- **Кто спрашивает, определяет только сессия.** Методы ученика не принимают `studentId`: чужие данные запросить нельзя, подмена параметров игнорируется.
- **Ученик не может менять** посещаемость, оценки, расписание и начисления EduCoins: эти операции (`staff.*`) доступны только ролям преподавателя (в своих группах) и администратора и проверяются на сервере.
- **EduCoins не хранятся числом.** Баланс = сумма журнала операций. Правила: присутствие +5, задание в срок +10, контрольная ≥90% +20, олимпиада +30, достижение +50 (один раз). Исправили отметку или оценку — начисление пересчитывается корректирующей записью. Обмен на награду проверяет баланс и остаток на сервере.
- **Посещаемость %** = (присутствовал + опоздал) / (присутствовал + опоздал + пропустил). Пропуски по уважительной причине в расчёт не входят.
- Демо-данные создаёт `js/server/seed.js` через те же операции, что и живая система (отметка посещаемости → баллы, проверка работы → оценка → баллы), поэтому каждое число прослеживается до записи.

## Известные ограничения
- Проекта-оригинала не было, поэтому всё создано с нуля. Кабинетов преподавателя, администратора и родителя в интерфейсе нет; готов их серверный API (`staff.*`), роли `teacher`/`admin` могут войти только через API.
- В режиме Live Server данные живут в браузере: технически подкованный пользователь может изменить localStorage. Настоящая защита — режим `node server.js`.
- Пароли хэшируются солёным SHA-256 с итерациями. Для боевого запуска замените на argon2/bcrypt.
- Перед запуском для реальных учеников: уберите `DEMO_ACCOUNTS` из `js/server/seed.js` и поставьте `SHOW_DEMO_HINT: false` в `js/config.js`.
- Файлы к заданиям (до 3 шт., до 1 МБ, pdf/png/jpg/doc/docx/txt/zip) хранятся прямо в базе (base64). Для больших объёмов нужно файловое хранилище.
- Фото профиля: показываются инициалы, загрузка фото не реализована.
- Время — локальное время центра, без часовых поясов.
- Проверено в Chromium. Safari и реальные телефоны не проверялись.

## Что добавлено во второй итерации

- **Фото профиля** (Профиль → «Загрузить фото»): файл обрезается по центру до 256×256 JPEG прямо в браузере, на сервере проверяется формат по сигнатуре файла и размер (SVG/HTML отклоняются). Фото видно только владельцу. Удаление — с подтверждением.
- **Экспорт журнала посещаемости**: кнопки «CSV» (UTF-8 с BOM, разделитель `;`, открывается в Excel; ячейки, начинающиеся с `=`, `+`, `-`, `@`, экранируются) и «Печать» (печатная версия без меню, всегда светлая, с шапкой отчёта).
- **Тёмная тема** (Настройки → Оформление): «Светлая» (по умолчанию) / «Тёмная» / «Как в системе». Выбор хранится на устройстве, мерцания при загрузке нет, при печати всегда светлая.
- Тесты: `npm test` — 19 backend-тестов; браузерные сценарии — `tests/e2e/` (Playwright: `crawl.cjs`, `flows.cjs`).

Ограничения: фото и тема хранятся в браузере/демо-базе; на статическом хостинге (Live Server) данные живут в localStorage конкретного браузера.

## Третья итерация: кабинет преподавателя

Вход: `index.html` → логин `nargiza`, пароль `Teacher#2026` (кнопка «Подставить» в блоке демо-доступа). Ученика и преподавателя форма входа сама отправляет в нужный кабинет: `student.html` или `teacher.html`.

Разделы: Главная (занятия сегодня, очередь проверки, неотмеченные занятия, ученики, требующие внимания), Посещаемость (отметка по занятию, массовое «Все присутствуют», причина пропуска, сохранение одним пакетом), Оценки, Задания и проверка (выдача, просмотр работ и файлов, оценка с комментарием), Группы и ученики (карточка, олимпиады), Расписание (отмена и перенос с уведомлением группы), Сообщения (рассылка группе), Профиль и настройки (тема, смена пароля).

Права проверяются на сервере (`js/server/backend.js`), а не в интерфейсе:
- преподаватель видит и меняет только свои группы; отмечает, отменяет и переносит только **свои** занятия; ставит оценки и выдаёт задания только по **своим** предметам; даты оценок в будущем и сроки сдачи в прошлом отклоняются;
- ученик получает `FORBIDDEN` на любой `staff.*` метод (роль проверяется раньше, чем существование объекта), а ученик и преподаватель не могут открыть чужой кабинет;
- пакетная отметка посещаемости атомарна: ошибка в одной строке не сохраняет ничего; баллы EduCoins пересчитываются по тем же правилам, что и при одиночной отметке;

Исправлено по пути: форма входа в режиме сервера могла отправиться обычным GET-запросом (пароль в адресной строке), если нажать «Войти» раньше окончания инициализации — обработчик теперь вешается синхронно.

Тесты: `npm test` — 22 backend-теста; `tests/e2e/teacher.cjs` — обход 8 страниц на 5 размерах экрана и 23 сценарные проверки (переменные `BASE`, `OUT`, `THEME=dark`).

## Четвёртая итерация: кабинет администратора

Вход: `admin` / `Admin#2026` (кнопка «Подставить»). Администратор попадает в тот же кабинет, что и преподаватель (все группы, все предметы), и дополнительно видит два раздела:

- **Аккаунты учеников** — создание ученика (логин, пароль, группа, контакты), отключение и включение доступа, сброс пароля. Отключённый ученик выходит из кабинета мгновенно, все его сеансы завершаются; при сбросе пароля старый перестаёт работать.
- **Награды и выдача** — очередь заявок («Выдано» или «Отменить»), каталог наград (цена, остаток, показ в магазине). При отмене заявки EduCoins возвращаются ученику отдельной записью `refund` в журнале, остаток награды восстанавливается, ученик получает уведомление. Возврат не считается заработком и рейтинг не меняет; выданную награду отменить нельзя, повторная отмена невозможна.

Права: все методы `admin.*` на сервере доступны только роли admin (ученик и преподаватель получают `FORBIDDEN`, проверено и по HTTP); у преподавателя разделов администратора нет ни в меню, ни по прямой ссылке.

Найдено тестами и исправлено: id новой награды мог совпасть с id демо-награды (`rw1`) и «редактирование» портило чужую запись — теперь берётся первый свободный id.

Тесты: `npm test` — 24 backend-теста; `tests/e2e/admin.cjs` — 18 сценарных проверок (создание аккаунта, вход нового ученика на все 10 страниц, отключение, обмен награды и возврат баллов). Все три набора e2e (`flows`, `teacher`, `admin`) пройдены в обоих режимах.

## Пятая итерация: структура центра (администратор)

Новый раздел **Группы и преподаватели** и кнопка **«Сменить группу»** в «Аккаунтах учеников»:

- создание преподавателя (логин, пароль, email, предметы из списка курсов) — он сразу может войти в кабинет преподавателя; пока у него нет занятий, кабинет пустой без ошибок;
- создание группы (название, курс, куратор), названия уникальны;
- перевод ученика в другую группу: оценки, посещаемость и EduCoins остаются у ученика, он получает уведомление, прежний преподаватель его больше не видит;
- добавление занятия в расписание с серверной проверкой: преподаватель должен вести этот предмет, предмет входит в курс группы, время в будущем, не длиннее 6 часов, **нет пересечений** по преподавателю, кабинету и группе (занятия «встык» допустимы); группа получает уведомление.

Исправлено по пути: кнопки длинных диалогов на узких экранах уходили за нижний край — подвал диалога теперь закреплён.

Тесты: `npm test` — 25 backend-тестов; `tests/e2e/admin.cjs` расширен сценарием группа → преподаватель → занятие (с отказом при двойном бронировании) → перевод ученика → вход нового преподавателя. Обходы вёрстки: преподаватель (8 страниц) и администратор (3 страницы) × 5 размеров, в обоих режимах.

## Шестая итерация: подготовка к реальному запуску

См. **DEPLOY.md** — пошаговая инструкция (первый запуск, HTTPS, systemd, Docker, резервные копии, проверка, ограничения).

- `EDUCENTER_MODE=production` — чистая база без демо-аккаунтов, единственный администратор из `ADMIN_LOGIN` / `ADMIN_PASSWORD` (слабый или пустой пароль при первом старте = сервер не запустится); на странице входа демо-подсказки нет.
- `GET /healthz` — проверка живости для хостинга и мониторинга (данные не раскрывает).
- `DATA_DIR` — где лежит база; `HSTS=1` — заголовок HSTS за HTTPS; корректное завершение по SIGTERM.
- `npm run backup` — копия базы с ротацией (`KEEP`), безопасно во время работы сервера.
- Тесты: `npm test` — 29 (25 backend + 4 процессных теста сервера: отказ без пароля, отсутствие демо-данных, перезапуск с сохранением данных, заголовки, закрытые файлы, копии).
